## Lifecycle and Semantics

- An SLA `AT_RISK` transition opens one escalation case, snapshots ticket/scope/workflow context, creates level 1 target assignments, appends `OPENED`, and audits `escalation_opened`.
- An SLA `BREACHED` transition promotes that same case to level 2 and trigger `BREACHED`, adds level 2 assignments, appends `PROMOTED`, and audits `escalation_promoted`. Level 1 assignment and history remain intact.
- If evaluation first observes a breach and the case is absent, the promotion action creates the case and records both `OPENED` and `PROMOTED` transitions.
- An acknowledged case remains `ACKNOWLEDGED` when promoted; current level and trigger change to level 2 / `BREACHED`. Acknowledgement does not affect SLA timing or resolution.
- SLA completion changes unresolved cases to `RESOLVED`; SLA cancellation changes them to `CANCELLED`. No manual resolution action is available while the SLA remains unresolved.
- Missing optional rules are a no-op for escalation creation; they do not block SLA transitions. Seeded-rule acceptance identifies missing defaults.
- Phase 9D notification delivery is intentionally excluded.

## Idempotency and Audit

History has unique idempotency keys and one event of each lifecycle type per case. Audit actions cover opened, promoted, acknowledged, resolved, cancelled, and rule create/update/activate/deactivate.

## Final Completion Classification Remediation and Acceptance

- **Root cause:** `sla_complete` previously relied on the state/timestamp branch while passing SQL `DATETIME` values from a view through Wappler's date serialization. Wappler treated the calendar-local wall-clock value as an instant and shifted it by the calendar offset on write. Classification therefore could not safely compare two calendar-local values unless the evaluator had already marked the SLA `BREACHED`.
- **Old classification:** an already-`BREACHED` instance was forced to `COMPLETED_OUTSIDE_SLA`; otherwise the action compared the view's converted completion value to `due_at`. The `BREACHED` shortcut alone did not cover overdue `ACTIVE`/`AT_RISK` instances, and the SQL `DATETIME` round-trip shifted the value.
- **New classification:** the Wappler library reads `due_at` and `completion_business_datetime` as fixed-format `YYYY-MM-DD HH:mm:ss.ffffff` strings. The database view derives the current local completion instant with `CONVERT_TZ(UTC_TIMESTAMP(6), '+00:00', sla_calendars.timezone_name)` and formats both values identically. The action classifies `BREACHED` or completion string `>` due string as outside; otherwise it is within. A NULL/unresolved conversion raises the existing `SLA_COMPLETION_CONFIGURATION` failure before mutation. The same canonical local string is written to completion/event/escalation timestamps.
